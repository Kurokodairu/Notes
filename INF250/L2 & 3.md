
## Histogram of an image
A histogram of an image is a graph that shows how pixel intensities are distributed in the image.
In simple words: A histogram tells us how many pixels have a particular brightness value

## Normalized histogram of an image
Instead of y-axis being number of pixels (frequency), it shows the probability density
![[Pasted image 20260914123327.png]]

Cant reconstruct an image using only its histogram
Histograms show no content, only statistical information, distribution of intensity values...

- Consider and image with intensity $r_{k}, k \ [0, L -1 ]$ and size $M * N$ (total pixels)
- The number of pixels with intensity $r_k$ is $n_{k}$
- The histogram of the image is the function $h(r_{k}) = n_k$
- The normalized histogram is the function $$ p(r_{k}) = \frac{n_{k}}{MN} \ for \ k = 0, \dots, L-1$$

## Brightness and contrast
Brightness -> Overall lightness or darkness of the image
Contrast -> the difference in brightness between objects or regions

A white rabbit runnning across a snowy field has poor contrast while a black dog against the same white background has good contrast

![[Pasted image 20260914124450.png]]

In the histogram brightness **shifts** all values to the right when brighter and the left for dark.

Contrast **moves** the points away from eachother creating more difference between the values in the histogram. the further to the edge the more the points gets moved more towards the edge.

#### Exposure
How much light the sensor collects
More light -> brigher pixels
Less light -> darker pixels

**Contrast** is understood as the range of intensity values effectively used within a given image, that is the difference between the image’s maximum and minimum pixel values. A full-contrast image makes effective use of the entire range of available intensity values from a = amin, . . . , amax with amin = 0, amax = K−1 (black to white)

#### Saturation
Pixel values hit the limit of the format (0 or 255 in 8-bit). In low light you often have shadow saturation (many values at/near 0). With strong light you can also get hightlight saturation (values at/near 255)

Why is it a problem? 
Saturation is information-destroying - many different real intensities collapse to the same clipped value - no detail to recover (sky turns posterized/white)

## Histogram of color images

#### Conversion of an RGB image to gray scale image
The conversion of an RGB color imageto a grayscale image proeeds by computing the equivalent gray or luminance value Y for each RGB pixel
A weighted sum of the color components is typically used for calculating the equivalent brightness or luminance in the form $$ Y = Lum(R,G,B) = w_{R}*R + w_{G}*G + w_{B}*B$$
We can either use the weights as 
$w_R$ = 0.299, $w_{G}$ = 0.587 $w_{B}$ = 0.114
or the weights recommended in ITU-BT.709[144] for digital color encoding are
$w_{R}$ = 0.2126 $w_{G}$ = 0.7152 $w_{B}$ = 0.0722

Histograms of color images
-> Typically what is meant is a histogram of the image intensity (luminance) or of the idividual color channels.


Histograms of an RGB color image: original image (a),
luminance histogram $h_{Lum}$(b),
RGB color components as intensity images (c–e),
and the associated component histograms $h_{R}$, $h_{G}$, $h_{B}$ (f–h).
The fact that all three color channels have saturation problems is only apparent in the
individual component histograms.
The spike in the distribution resulting from this is found in the middle of the luminance
histogram (b).

The saturation problems in all three channels (red in upper intensity and green blue in lower region) are obvious in the component histograms but not in the luminance histograms.


![[Pasted image 20260914132448.png]]

Luminance and component histograms shows hot bright or dark the image is, and how each color channel (rbg) behaves on its own. But they cannot tell ou anything about the actual colors in the image - bc real colors are mode by mixing the channels together 
$$ h_{R}(50) = 100, \ h_{G}(50) = 100, \ h_{B}(50) = 100 $$
Three component histograms with these entries -> image contains 100 pixels with the color combination $(r,g,b) = (50,50,50)$
In general, no, because there is no way of ascertaining from these data if there exists a pixel in the image in which all three components have the value 50. The only thing we could really say is that the color value (50,50,50) can occur at most 100 times in this image.

So, although conventional (intensity or component) histograms of color images depict
important properties, they do not really provide any useful information about the composition
of the actual colors in an image.
In fact, a collection of color images can have very similar component histograms and still
contain entirely different colors

## Histogram equalization
It is an image enhancement technique that improves the contrast of a grayscale image by redistributing its pixel intensity values over a wider range. It uses the image histogram and its cumulative distribution function (CDF) to compute a new intensity mapping

Why?
To improve the visibility of details in images with low contrast
To make dark regions brighter and bright regions more distiguishable
To spread pixel intensities more evenly across the available intensity range.
To improve the quality of images for visual inspection and as a preprocessing step for computer vision and image analysis tasks.
