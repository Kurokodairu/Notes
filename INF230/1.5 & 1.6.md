
# 1.5 Foundational ontologies

## What is a foundational ontology?

A **foundational ontology** describes the most fundamental categories of things that exist.

It asks questions such as:

> What fundamentally exists?

> What is an object?

> What is a process?

> How do objects and processes relate?

Used as a common basis for more specific ontologies.

```
Foundational ontology
        ↓
Middle-level ontology
        ↓
Domain ontology
        ↓
Application ontology
```

Important foundational ontologies in the lecture:

```
BFO
DOLCE
EMMO
```

---

# Mereology

**Mereology** = study of **parts and wholes**.

Example:

```
Car
 ├── Engine
 ├── Wheels
 └── Doors
```

Questions include:

```
What is part of what?
How do parts form a whole?
```

---

# Endurantism vs Perdurantism

One of the **most important concepts** in this lecture.

## Endurantism

An **endurant** maintains its identity through time.

It can have spatial parts, but not temporal parts.

Example:

```
Person
```

A person can be:

```
child → adult
```

but we still refer to the same person.

### BFO

BFO is associated with **endurantism**.

Important terms:

```
Continuant / Endurant
→ thing that persists through time

Occurrent / Perdurant
→ process/event that unfolds through time
```

---

## Perdurantism

A thing is understood through its **temporal parts**.

Example:

```
Person-at-time₁
Person-at-time₂
Person-at-time₃
```

The object/process is understood as a four-dimensional entity extended through **space and time**.

### EMMO

EMMO is associated with **perdurantism / four-dimensionalism**.

---

## 🔥 Exam comparison

||Endurantism|Perdurantism|
|---|---|---|
|Main idea|Object persists through time|Things have temporal parts|
|Object|Exists as the same thing through time|Viewed as extended through time|
|Time|Object does not have temporal parts|Temporal parts are fundamental|
|Associated ontology|**BFO / DOLCE**|**EMMO**|

### Easy memory trick

```
ENDURANT
= thing ENDURES through time

PERDURANT
= thing is spread through time
```

# BFO

**BFO = Basic Formal Ontology**

Main idea:

```
Reality contains
→ continuants
→ occurrents
```

### Continuant

Something that persists.

Examples:

```
person
object
material entity
```

### Occurrent

Something that happens/unfolds.

Examples:

```
process
event
```

BFO is strongly influenced by:

- dependence
- boundaries
- parthood / mereology

---

# DOLCE

**DOLCE = Descriptive Ontology for Linguistic and Cognitive Engineering**

Main idea:

> A descriptive ontology focusing on categories useful for language, cognition and common-sense conceptualization.

DOLCE distinguishes among things such as:

```
Endurants
Perdurants
Qualities
Abstracts
```

---

## DOLCE: Quality vs Quale

Important distinction.

### Quality

A property that an object has.

Example:

```
Flower
 ↓
has quality
 ↓
Colour
```

### Quale

The **value** of the quality.

Example:

```
Quality = colour
Quale = red
```

So:

```
Flower
   ↓
colour quality
   ↓
red quale
```

### Easy way to remember

```
Quality = what kind of property?
Quale   = which value?
```

Example:

```
Temperature → quality
20°C        → quale
```

---

# DOLCE: Participation

DOLCE uses the relation **participation** between endurants and perdurants.

Example:

```
Person ──participates in──> Lecture
```

The person is an **endurant**.

The lecture is a **perdurant**.

# Semiotics

## Peirce's semiotic triangle

Three important elements:

```
Sign
 ↓ represents
Object

Interpretant
 ↓
new understanding / representation
```

More explicitly:

```
        Object
       /      \
 represents    represents
     /          \
   Sign ----> Interpretant
```

### Terms

**Sign / representamen**

Something that represents something else.

**Object**

What the sign refers to.

**Interpretant**

The new sign/understanding produced through interpretation.

---

# Semiosis

**Semiosis** = the process through which a sign leads to the creation of a new interpretant/sign.

```
Sign → interpretation → new sign
```

---

# Metonymization

**Metonymization** = a representamen becomes associated with a **new referent/object**.

In other words:

```
same sign
   ↓
new referent
```

---

# Research workflows as cognitive processes

The lecture connects Peircean semiotics to scientific workflows.

Example:

```
Experimental data
      ↓
    model
      ↓
 simulation
      ↓
 simulation result
```

Each stage creates a new **representation** of the same underlying object/material.

Important idea:

> A cognitive step starts from one representation relation and creates another.

---

# Mereosemiotics

**Mereosemiotics** combines:

```
Mereotopology
+
Peircean semiotics
```

The purpose is to reason about both:

```
parts / wholes / spatial-temporal relations
```

and

```
signs / representations / interpretation
```

This is particularly relevant to the EMMO-style 4D view.

# 1.6 Semantic heterogeneity

## What is semantic heterogeneity?

Different systems use **different metadata standards/ontologies** to represent similar information.

Example:

```
System A                System B

Book                    BookArtefact
author                  hasCreator
Person                  Author
```

Even when two systems describe the same real-world domain, their:

- terminology
- classes
- properties
- graph structures

may differ.

---

# Why is it difficult?

The problem is often **more than different words**.

The actual **shape/structure of the knowledge graph** can be different.

```
Ontology A
A → relation → B

Ontology B
A → object → C
C → relation → B
```

So a simple 1:1 name replacement may not be enough.

---

# Ontology alignment

**Ontology alignment** = establishing correspondences between concepts/relations in different ontologies.

Example:

```
Ontology A: Book
        ↕
Ontology B: BookArtefact
```

The goal is to allow data represented using one ontology to work with another.

---

# SKOS

**SKOS = Simple Knowledge Organization System**

Can be used to describe **concept schemes** and mappings between them.

Important mapping relations from the slides:

```
skos:exactMatch
skos:broadMatch
skos:narrowMatch
```

---

## exactMatch

Two concepts are considered equivalent.

```
A:book
   ↓ exactMatch
B:BookArtefact
```

Think:

```
A ≈ B
```

---

## broadMatch

The target concept is **broader/general**.

```
A:author
   ↓ broadMatch
B:hasCreator
```

So the correspondence is not necessarily 1:1 in meaning.

---

## narrowMatch

The target concept is **more specific**.

```
A:person
   ↓ narrowMatch
B:Author
```

Think:

```
Person
  ↓
Author
```

An author is a narrower category than a person.

---

# Graph transformation

Sometimes simple SKOS mappings aren't enough because the **graph structure itself differs**.

Then we transform the graph.

Conceptually:

```
Source graph
      ↓
transformation rules
      ↓
Target graph
```

The slides describe using **SPARQL** to formulate these transformation rules.

---

# STTL

**STTL = SPARQL Template Transformation Language**

Used for transforming RDF/knowledge graphs using SPARQL-based templates.

Think:

```
RDF graph
   ↓
SPARQL/STTL transformation
   ↓
new RDF graph
```

---

# Semantic interoperability

## Goal

Different systems should be able to **exchange and understand information consistently**.

Approaches discussed:

```
1. Reuse existing ontologies
2. Align ontologies
3. Map concepts using SKOS
4. Transform graph structures using SPARQL/STTL
5. Use foundational ontologies as a common basis
```

---

# Foundational ontologies for alignment

Foundational ontologies can help different domain ontologies establish a **shared conceptual basis**.

The lecture mentions the **OntoCommons ecosystem**, involving:

```
BFO
DOLCE
EMMO
```

and the use of **bridge concepts** for ontology alignment.
